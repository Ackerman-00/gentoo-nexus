## Run summary

### BLOCKER RESOLVED — empty local binrepo index root-caused and fix verified

The recurring CI failures (sqlite FORCE REBUILD gpm↔ncurses cycle, then
librsvg/heroic-bin rust-bin failure) are **one root cause**: the CI
"Restore GPKG Layout" step places `.gpkg.tar` files into `category/`
directories only (`target_dir = os.path.join(pkgdir, cat)`), but portage
`_populate_local()` (verified against portage-3.0.81 source, saved at
`/tmp/opencode/pop-local-src.txt`) **silently skips multi-instance gpkg
files** (BUILD_ID > 0, e.g. `gpm-1.20.7-r6-20.gpkg.tar`) unless they live in
`category/packagename/` subdirectories. Result: `emaint binhost --fix`
regenerates an **empty index (PACKAGES: 0)** every build → the entire nexus
binrepo is invisible → target packages degrade to source builds → circular
dependencies / unmet 32-bit deps.

**Verified in docker** (stage3 desktop-openrc, quickstart config):

| Layout (531 files) | `emaint binhost --fix` | Index |
|---|---|---|
| `category/` (current CI) | with or without `rm -f Packages` | **0 CPVs** |
| `category/packagename/` (portage-native) | same | **529-530 CPVs** (gpm, ncurses, mesa, rust-bin all present) |

Failure chains reproduced exactly:
- **Run 32131084168 (sqlite force-rebuild):** empty index → gpm `[binary Rg]`
  pulled from the official v3 host (has abi_x86_32), ncurses has no
  `[abi_x86_32+gpm]` binary anywhere → ncurses source rebuild → `gpm→ncurses`
  vs `ncurses(+gpm)→gpm` circular dependency.
- **Run 32108263185 (heroic-bin 2.22.1):** `librsvg-2.62.3[abi_x86_32]`
  requires `>=dev-lang/rust-bin-1.92.0[abi_x86_32]`. Nexus release HAS
  `rust-bin-1.95.0` with abi_x86_32 (metadata verified) but the empty index
  made it invisible; official v3 host ships no rust-bin[abi_x86_32] →
  "no ebuilds built with USE flags to satisfy".

**Fix (owner must apply to both workflows):**
1. **Part 1 (necessary):** restore step target_dir →
