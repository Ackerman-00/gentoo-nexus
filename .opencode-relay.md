## Root cause & fix

### Root cause
All force rebuilds fail because of a gpm ↔ ncurses circular dependency.
The consumer config enables `sys-libs/ncurses gpm` (from nexus package.use),
but the official binhost's ncurses lacks the `gpm` USE flag. This means
consumers must build ncurses from source with gpm USE, which depends on gpm.
Building gpm from source depends on ncurses → circular.

### Fix applied (no workflow push needed)
The correct binaries are now in the rolling release:
- `gpm-1.20.7-r6-20.gpkg.tar` — USE: abi_x86_32 abi_x86_64 amd64 elibc_glibc kernel_linux
- `ncurses-6.5_p20251220-4.gpkg.tar` — USE: abi_x86_32 abi_x86_64 amd64 cxx elibc_glibc gpm kernel_linux stack-realign tinfo

Both were built from source in a clean stage3 container:
1. Build ncurses WITHOUT gpm (no gpm dependency)
2. Build gpm (depends on ncurses, now available as binary)
3. Rebuild ncurses WITH gpm (depends on gpm, now available as binary)

The Packages index was updated to include the gpm entry with correct USE.
When build.yml runs (on origin/main, WITHOUT pre-build fix), Portage pulls
both gpm and ncurses as matching binpkgs → no source build → no circular dep.
