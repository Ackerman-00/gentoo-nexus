### BLOCKER — workflow fixes verified but pushable only by owner (confirmed)

The single root cause of the recurring Build Relay failures is **confirmed**:

- Portage `_populate_local()` (bintree.py, portage-3.0.81 in
  gentoo/stage3:amd64-desktop-openrc) **silently skips multi-instance gpkg
  files** (BUILD_ID > 0) unless they live in `<pkgdir>/<category>/<pn>/`
  subdirectories.
- The current "Restore GPKG Layout" step in both build.yml and
  build-gentoo-official.yml places files in flat `<category>/` dirs →
  `emaint binhost --fix` regenerates an **empty Packages index (PACKAGES: 0)**
  → whole nexus binrepo invisible → source rebuilds → gpm/ncurses circular
  deps.

**Fix:** Change layout from `<category>/` to `<category>/<pn>/` in both
workflows' "Restore GPKG Layout" step, plus broaden the gpm/ncurses heal
trigger to also check `abi_x86_32`. Full diffs posted to issue #5 (comments
5336304243 + 5336304787). **Owner must apply from a local checkout** — the
GitHub App token lacks `workflows` scope, so the fix cannot be pushed.
