**Blocker 1 (NEW this run) — rust-bin `abi_x86_32` use-dep unsatisfiable**
kills heroic-bin, librsvg-2.62.3, libsdl3, openal (the "Build Gentoo Official"
chain, 12+ consecutive failures 32282194912 → 32303794618):

```
emerge: there are no ebuilds built with USE flags to satisfy ">=dev-lang/rust-bin-1.92.0:*[abi_x86_32(-)?,abi_x86_64(-)?,abi_x86_x32(-)?,abi_mips_n32(-)?,abi_mips_n64(-)?,abi_mips_o32(-)?,abi_s390_32(-)?,abi_s390_64(-)?]".
- dev-lang/rust-bin-1.97.1::gentoo (Change USE: +abi_x86_32)
- gnome-base/librsvg-2.62.3::gentoo (Change USE: -abi_x86_32)
```

Root cause: librsvg sets `RUST_MULTILIB=1` → rust.eclass appends
`${MULTILIB_USEDEP}` to the rust dep, producing
`|| ( >=dev-lang/rust-bin-1.92.0:*[abi_x86_32(-)?,...] >=dev-lang/rust-1.92.0:*[abi_x86_32(-)?,...] )`.
`dev-lang/rust-bin` has NO `abi_x86_32` IUSE (verified in ::gentoo), and per the
devmanual `[flag(-)]` semantics a missing flag is assumed disabled, so the
use-dep can never be satisfied by rust-bin. Portage commits to the FIRST any-of
member (`rust-bin`) and never backtracks to `dev-lang/rust` source (which DOES
have `abi_x86_32` via multilib-build) — reproduced in docker with rust-bin
masked, source-only, and with the full gaming USE set. The **only** thing that
makes librsvg resolve is a rust-bin binary whose recorded USE contains
`abi_x86_32`.

Why May 28 worked: the old `gentoo-build.yml` era (run 26551932530) used global
`USE="vaapi vdpau vulkan amdgpu ffmpeg encode nvenc elogind egl -systemd -cups
abi_x86_32"`, so the built rust-bin-1.95.0 asset records `abi_x86_32` (verified
in the rolling Packages index: `USE: abi_x86_32 abi_x86_64 amd64 clippy
cpu_flags_x86_sse2 doc elibc_glibc kernel_linux llvm_slot_22 rustfmt`).
librsvg-2.62.2-r1 then built against it. The new `build-gentoo-official.yml`
uses per-package USE only and DROPPED the rust/rust-bin lines from the GAMING
heredoc → no rust-bin binary with abi_x86_32 is produced → librsvg blocker.

**Blocker 1 fix (docker-verified this run, repro8):** add the two inert lines
to the GAMING heredoc in BOTH `build.yml` and `build-gentoo-official.yml`
(byte-identical heredocs; quickstart.sh steam block already has them at lines
334-335):

```
dev-lang/rust abi_x86_32
dev-lang/rust-bin abi_x86_32
```

With these lines `emerge --pretend =gnome-base/librsvg-2.62.3` resolves and
schedules `dev-lang/rust-bin-1.97.1` with `ABI_X86="32* (64)"` (repro8). The
inert flag is recorded in the built binpkg USE → librsvg's `[abi_x86_32(-)?]`
use-dep satisfied. Without the lines the exact CI error reproduces (repro2).
