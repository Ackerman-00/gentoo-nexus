### Root cause analysis: gpm/ncurses circular dependency
The cycle was identified from build logs of failed runs 32002761753 and 32000639067:
```
(sys-libs/gpm binary) depends on (sys-libs/ncurses ebuild, runtime_slot_op)
  (sys-libs/gpm binary, buildtime)
```

**Root cause:** Nexus ncurses binary was built WITHOUT `gpm` USE (visible in Packages index:
`USE: abi_x86_32 abi_x86_64 amd64 cxx elibc_glibc kernel_linux stack-realign tinfo`), but the
build config requires `sys-libs/ncurses gpm`. Binary rejected → source rebuild → cycle with
gpm binary's runtime_slot_op on ncurses.

**Fix (saved locally, cannot push):** After perl-cleaner, force BOTH ncurses and gpm to source
build using `--usepkg-exclude` so portage can resolve the build order internally. The fix also
applied to build-gentoo-official.yml.
